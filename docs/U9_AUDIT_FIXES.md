# U9 独立审计（2026-10-22）问题修复说明

针对《U9第三版独立审计报告》中的 F-1 至 F-4 和 G1。基线 `b2e53f4`。

| 编号 | 问题 | 修复 | 回归测试（`tests/test_u9_audit_fixes.py`） |
|---|---|---|---|
| F-1 | 快照为空的旧单据开工时静默冻结当前 BOM，无提示、无技术确认 | 没有 BOM 快照 = **待技术确认**。确认前不能开工、领料（建单/过账）、报工、退料；系统不再自动选版本。技术用 `POST /work-orders/{id}/bom-confirm`、`POST /outsource/{id}/bom-confirm` 选定版本（可选已作废的旧版，或沿用关联订单批准版），必须填依据，与已领料/已报工核对后给出提示，留痕（确认人/时间/依据/审计日志）。`GET …/bom` 返回候选版本和已领料情况；列表支持 `bom_pending=true`；预警中心新增"待确认BOM"（发给技术），确认后自动关闭；前端自制任务、外协单页加"待技术确认BOM"标签和确认弹窗。包工包料外协不投料，不受影响 | 11 项 |
| F-2 | 同一期初库存文件重复导入（顺序或并发）库存翻倍 | 同一（物料、仓库、批次号）在库里只允许存在一次（已领空的批次也算），同文件内重复也拒绝；整批拒绝，预检同样报出 | 8 项 |
| F-3 | 外协已发出后取消，已出库的料悬空 | 只有"待发出"状态能取消；已发出须先 `POST /outsource/{id}/recall`（填原因，且外协厂无任何回厂记录）退回待发出，原料随即可退。同时修了一个关联缺陷：待发出状态领了料再取消，退料口径把"非计划状态"都当已消耗，料被锁死 | 7 项 |

## 迁移
`c7d2e4f1a903`：自制任务/外协单增加 `bom_confirmed_by / bom_confirmed_at / bom_confirm_note`。不改写任何已有数据：迁移前没有快照的单据自动显示为"待技术确认"。SQLite、MySQL 8.0.46 均验证 `upgrade head`、`alembic check`、`downgrade -1`。

## 上线注意
- 升级后，快照为空的在制自制任务和本厂供料外协单会全部进入"待技术确认"，**需要技术先逐张确认**，否则这些单据不能开工/领料/报工/退料。预警中心和 `?bom_pending=true` 可以列出清单。
- 已取消/已完工的旧单据如果还有已过账领料单，要退料同样需要先确认（确认不限单据状态）。
